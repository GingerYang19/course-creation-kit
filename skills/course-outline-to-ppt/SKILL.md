# 课程大纲 → PPT 自动生成

## 触发场景

- 用户提供课程大纲，要求生成 PPT 课件
- 用户要求更新/刷新已有课件内容
- 用户提供参考资料，要求据此生成课件

## 工作流总览

```
判断任务类型
├─ 新建课件 → Generation Flow
└─ 更新课件 → Update Flow
    ├─ 用户有明确更新方向 → 按指令更新
    └─ 用户无明确方向 → 自动搜索更新
```

---

## Generation Flow（新建课件）

### Step 1：收集信息

确认以下要素（已提供的跳过）：

| 要素 | 说明 | 默认值 |
|------|------|--------|
| 课程大纲 | 文本/文件/图片均可 | 必须 |
| 目标页数 | 用户指定或根据大纲推算 | 大纲章节数×2~3 |
| 受众与语气 | 企业培训/高校/内部分享等 | 企业培训 |
| 参考资料 | 文件路径/粘贴文本/无 | 无 |
| 视觉模板 | 6 套内置主题之一，见 Step 1.5 | 按主题自动匹配 |

页数推算规则：
- 用户明确指定 → 严格遵循
- 未指定 → 每个大纲章节分配 2-3 页（含 1 页封面 + 1 页结尾），总页数 = 章节数×2.5 + 2，取整

### Step 1.5：选择视觉模板

本技能内置 6 套美观的视觉主题（配色+字体+母题）。定义见 `templates/themes.json`，画廊与选用指南见 [templates/themes.md](templates/themes.md)，生成器调用见 `templates/themes.py`。

选择规则：
- 用户已指定风格（"要科技感""暖一点""商务汇报"）→ 按 themes.md 的"按课程主题自动匹配"表直接选定，不必再问
- 用户未指定 → 用 AskUserQuestion 给 3 个最贴合课程方向的选项让用户挑，默认推荐自动匹配的那套
- 拿不准 → 用 `deep-space`（最通用）

6 套主题 id：`deep-space` 深空觉醒 / `scholar-green` 墨绿学术 / `warm-terracotta` 暖橙人文 / `executive-slate` 商务灰金 / `porcelain-teal` 青瓷科技 / `aubergine-premium` 绛紫高定。

选定后记录 theme id，在 Step 5 生成时应用。所有主题均为实色配色，已规避紫渐变、深蓝霓虹等 AI-slop 组合。

### Step 2：解析大纲

将大纲结构化为页面计划：

```
页面计划 = [
  { "page": 1, "type": "cover", "title": "课程名称", "subtitle": "副标题/讲师信息" },
  { "page": 2, "type": "toc", "title": "目录", "items": [...] },
  { "page": 3, "type": "section", "title": "章节标题", "bullets": [...] },
  ...
  { "page": N, "type": "closing", "title": "总结/感谢", "bullets": ["要点回顾..."] }
]
```

大纲层级映射：
- 一级标题 → section divider 或独立内容页
- 二级标题 → 内容页标题
- 三级要点 → 页面 bullets
- 若大纲层级不足，根据主题合理扩展（但不得编造具体数据/案例）

### Step 3：处理参考资料（如有）

1. 读取用户提供的参考文件（PDF/DOCX/TXT/MD/图片）
2. 提取与大纲各章节对应的关键内容
3. 将提取内容融入对应页面的 bullets 和要点中
4. 参考资料中的原文表述优先保留，不做无意义改写
5. 若参考资料覆盖不全的章节，用通用知识补充并标注"[补充内容]"

### Step 4：生成每页内容

遵循密度与丰富度规范（详见 [content-density.md](content-density.md)）。核心要求是**每页都要"厚实"**，杜绝"几条干要点"的单薄感：

- 标题：≤ 18 个中文字符
- 内容页采用「主点 + 副线」分层结构：3-5 组，主点 15-30 字、副线 20-45 字
- 内容页总文字量：160-320 个中文字符（不含标题）
- 每个内容页至少 1 条要点带场景化案例或类比（副线中用"例如/就像"引出）
- 禁止整段文字堆砌，也禁止只有主点没有副线的单行要点

**版式选择（每 2-3 页至少 1 页用可视化替代纯要点）**，实现参照 pptx 技能 `references/python_pptx_recipes.md`：

| 内容特征 | 版式 |
|----------|------|
| 两个对立/并列概念 | 对比双栏 / Before-After |
| 有先后顺序的流程 | 编号步骤 / 时间线 + 箭头 |
| 多个并列分类 | 多列卡片（2-4 列） |
| 关键数字/结论 | 数据卡片 / 大字报 |
| 多维属性对照 | 表格（行=对象，列=维度，≤5行×4列） |
| 层级/包含关系 | 嵌套框图 |

内容生成原则：
- 教学逻辑：先概念→再解释→后应用/案例
- 每页只讲一个核心点，但用「主点+副线」把它讲透
- 用动词开头写主点（"掌握…""理解…""应用…"）
- 副线负责解释/举例/给数据，不得只是换词重复主点
- 数据用概数增强说服力（不得编造精确数字与真实公司案例）
- 章节间有过渡衔接

### Step 5：调用 pptx skill 生成文件

按照 pptx skill 的五步快速路径执行：
1. 环境检查（python-pptx + markitdown）
2. 编写 generate.py（含配色、版式、内容）
3. 执行并自检
4. 交付

设计要求：
- **视觉模板**：从 `templates/themes.py` 导入所选主题的 palette 与字体（`get_theme(theme_id)` + `build_pptx_palette(theme)`），不要手写配色
- 封面页包含课程名、副标题、讲师/机构信息，封面用主题的 dominant/deep 深底 + accent 火花
- 内容页使用主题 accent/accent2 双色条或编号圆点作为视觉锚点
- 章节分隔页用大字标题+简洁引导语
- CJK 字体：按主题 fonts 字段设置（默认 PingFang SC，scholar-green 标题用 Songti SC）

### Step 6：交付

调用 present_files 展示 .pptx，附一段 QA 说明。

## Update Flow（更新课件）

### 判断更新类型

**用户有明确更新想法**（如"把第3章换成XX内容""增加一页关于XX"）：
1. 读取现有课件内容（markitdown 提取文本）
2. 定位需修改的页面
3. 按用户指令重写对应页面内容
4. 保持其余页面不变，重新生成完整 .pptx
5. 交付时说明修改了哪些页面

**用户无明确方向，只要求"更新/刷新"**：
1. 读取现有课件，提取课程主题和各章节关键词
2. 用 WebSearch 搜索课程主题的最新动态、案例、数据（限近 1 年）
3. 搜索策略：
   - 主题关键词 + "2026" / "最新" / "趋势"
   - 主题关键词 + "案例" / "实践"
   - 至少搜索 2-3 组不同角度的关键词
4. 从搜索结果中筛选与课程内容相关的新材料
5. 生成更新建议清单，展示给用户确认：
   ```
   建议更新：
   - 第X页：原内容"..." → 建议替换为"..."（来源：...）
   - 第Y页：建议新增要点"..."
   ```
6. 用户确认后执行更新，重新生成 .pptx
7. 交付时标注更新内容和信息来源

### 更新原则

- 保持原有课件的整体结构和设计风格不变
- 只更新内容，不改变版式（除非用户要求）
- 新增内容需与原有内容风格一致
- 搜索到的信息需注明来源
- 不确定的信息标注"[待确认]"

## 质量检查清单

生成/更新后自检：

- [ ] 每页文字量在密度规范内（不过载/不过空）
- [ ] 内容页均为「主点+副线」分层，无单行干要点
- [ ] 每 2-3 页至少有 1 页用了对比/流程/多列/表格/数据卡等可视化版式
- [ ] 每个内容页至少有 1 条场景化案例或类比
- [ ] 大纲所有知识点均已覆盖
- [ ] 无编造的精确数据或虚假案例
- [ ] 参考资料内容已正确融入（如有）
- [ ] 页面间逻辑连贯，有教学递进感
- [ ] CJK 字体正确设置，无乱码，无溢出截断省略号
- [ ] 文件名含课程主题，存于 outputs/

---

## 注意事项

- 大纲为图片时：先 Read 图片识别文字，逐字提取大纲内容，不得推测
- 大纲为文件时：读取全文后再结构化
- 页数冲突时：用户指定页数 > 自动推算页数
- 参考资料与大纲冲突时：以参考资料为准（用户提供的更权威）
- 更新搜索无结果时：告知用户未找到新材料，建议用户提供更新方向
